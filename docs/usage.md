# 使い方ガイド（かんたん版）

Discord のメッセージを Claude Code に「これ見て、なんとかして」と投げられる Chrome 拡張の使い方です。
むずかしい言葉はなるべく使わずに説明します。

---

## 1. 全体のしくみ（30秒でわかる）

```text
Discord Web のメッセージ
   ↓ 「Claude」ボタンを押す
Chrome 拡張（送信画面 + Side Panel）
   ↓ HTTP で送る
Bridge（自分のPCで動く小さなサーバー）
   ↓ claude コマンドを起動
Claude Code（いつも使っているやつ）
   ↓ 結果がリアルタイムで戻る
Chrome の Side Panel に表示
```

- **Bridge** = Chrome と Claude Code の間に立つ通訳さん。自分のPC（または同じ Wi-Fi 内の別PC）で動かします。
- **Side Panel** = Chrome の右側に出るパネル。Claude の返事を読んだり、追加でお願いしたりする場所です。
- **Claude Session** = 1回の「お願い」から始まる会話のかたまり。あとから続けて指示できます。

---

## 2. 最初の準備（1回だけ）

macOS / Windows / WSL2の導入は [社内向け導入ガイド](setup.md) を参照してください。Node.js 22以上、環境に対応するClaude Code CLI、Google Chromeを使います。

初期設定後は、展開フォルダで次を実行するとBridgeが起動します。

```sh
node bridge/src/index.js
```

自動起動を登録済みなら、この操作は不要です。Discord Webを開き、次の操作へ進みます。

---

## 3. 基本の使い方：メッセージを Claude に投げる

1. Discord でメッセージにマウスを乗せる → 右上のアクション（リアクション、返信…）の横に **Claude** ボタンが出る
2. 押すと「Claudeへ送る」画面が開く
3. 画面の中身:
   - **Source Message** … 選んだメッセージのプレビュー
   - **Message Context** … 一緒に送るメッセージ一覧（チェックで ON/OFF）。「前5件を追加」「後5件を追加」で周りの会話も足せる
   - **Action Preset** … やってほしいことのテンプレ（Jiraに起票 / GitHub Issue化 / 要約 / 調査 / 批評 / 自由入力）
   - **作業先** … ふつうは「一般」のまま。コードを直してほしいときだけ「Projectを選択」でリポジトリを選ぶ
   - **追加指示** … 自由に書く欄。Preset と組み合わせてもいいし、自由入力だけでもいい
4. 「Claudeへ送信」を押す → 右に Side Panel が開いて Claude の返事が流れてくる
5. 終わったら「最終回答をコピー」でクリップボードへ

### 返信メッセージを選んだとき
返信（リプライ）の場合は、**その返信の元をたどった会話 + そのメッセージへの返信** が自動でまとめて選ばれます。関係ない枝分かれは入りません。20件を超えると「多いよ」と注意が出ますが、そのまま送れます。

### 添付ファイル
画像・PDF・テキスト・ソースコード・JSON・ログなどは Bridge が自動でダウンロードして Claude が読めるようにします（24時間で自動削除）。
動画や音声は大きいのでダウンロードせず、ファイル名と URL だけ Claude に伝えます。

---

## 4. Side Panel でできること

Side Panel の上半分はセッション一覧、下半分がいま開いているセッションです。

| ボタン / 欄 | なにが起きる |
|---|---|
| **追加指示** → 送信 | 同じ Claude Session に続けてお願いできる（「この内容で Jira に起票して」など） |
| **停止** | 実行中の処理だけ止める。セッションは残るので、また指示できる |
| **最終回答をコピー** | Claude の最後の返事をコピー |
| **Discordコンテキストを更新** | Discord 側で会話が進んだとき、**まだ送っていないメッセージだけ** を一覧で見せてくれる。チェックして「Current Session に追加」で同じセッションに足せる（自動では絶対に取り込まない） |
| **Projectで続行 (Handoff)** | 「一般」で調査していた内容を、リポジトリでの実装作業に切り替えるとき使う（次の章） |
| **ターミナルで開く** | 同じ PC で Bridge が動いていれば、Terminal.app が開いて同じセッションを `claude --resume` で続けられる |
| **resumeコマンドをコピー** | Bridge が別 PC のとき用。`cd "<フォルダ>" && claude --resume <id>` をコピーして、その PC で貼り付けて実行 |

拡張アイコンの赤いバッジは「終わったけどまだ見てないセッションの数」です。開けば消えます。

### セッション一覧のルール
- 一覧は Chrome 側に「目次」を持っているだけで、本体は Claude Code のセッションです
- Side Panel を開くたびに Claude Code 側を確認し、消えていたセッションは一覧からも自動で消えます
- 削除ボタンやアーカイブはありません（Claude Code の保存期間にそのまま従います）

---

## 5. 調査 → 実装に進みたいとき（Handoff）

「一般」で調査してもらって、「よし、これ直そう」となったら:

1. Side Panel で **Projectで続行 (Handoff)** を開く
2. リポジトリを選ぶ（必要なら追加指示も）
3. 「Handoff を生成して Project Session を開始」

すると Claude が元の会話から **引き継ぎメモ（調査結果 / 決定事項 / Discord のリンク / 関連リンク / 今わかっている問題 / 次にやること）** を作り、それを最初の指示にして、選んだリポジトリで **新しいセッション** が始まります。

- 元の調査セッションはそのまま残ります（書き換えません）
- 新しいセッションには「元セッション: ○○」リンクが表示されるので、いつでも戻れます

---

## 6. 別のメッセージを今のセッションに足したいとき

Side Panel でセッションを開いたまま Discord の別のメッセージで **Claude** ボタンを押すと、送信画面の上に

```text
(•) 新しいセッションを開始   ( ) 現在のセッションに追加: ○○
```

が出ます。「現在のセッションに追加」を選ぶと、そのメッセージ（と選んだ周辺の会話）が今のセッションに追記されます。ふつうは「新しいセッションを開始」のままで OK。

---

## 7. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 「Claude Bridgeに接続できません」 | Bridge のターミナルが動いているか。拡張のオプション画面で「接続テスト」 |
| Claude ボタンが出ない | Discord Web をリロード。拡張を再読み込みしたあとも Discord のリロードが必要 |
| 「Discordコンテキストを更新」で「チャンネルを開きました。もう一度押してください」 | Discord タブが別のチャンネルにいたので移動しただけ。読み込み後にもう一度押せば OK |
| 「ターミナルで開く」が出ない | Bridge が別 PC で動いているか、`terminalCommand` が空。「resumeコマンドをコピー」を使う |
| 「〇〇 の実行権限が許可されていない」と返ってくる | 非対話モードでは許可ダイアログが出せないため。`workspace` フォルダの `.claude/settings.json` に `"permissions": { "allow": ["mcp__claude_ai_Atlassian", "Bash(gh issue create:*)"] }` のように事前許可を書く（[設定リファレンス](reference.md)「非対話モードのツール許可」参照） |
| Claude 側でエラー | Side Panel にエラー文が出て、その実行は終わり。同じセッションに追加指示すれば続けられます（自動リトライはしません） |

---

## 8. 覚えておくと便利なこと

- Claude の権限（ファイル編集、git、MCP など）は **いつも使っている Claude Code の設定がそのまま** 使われます。拡張が勝手にゆるめたり厳しくしたりはしません
- `workspace` フォルダに `CLAUDE.md` や MCP 設定を置くと、「一般」のお願いのときにそれが効きます（Jira や GitHub の MCP をここに置くのがおすすめ）
- Action Preset を増やしたいときは `bridge/config.json` の `actions` に `{ "id", "label", "prompt" }` を足して Bridge を再起動するだけ。拡張側の変更は不要です
- Bridge には認証がありません。使わないときは止めておきましょう
